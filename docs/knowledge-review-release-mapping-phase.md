# Source-bound reviewed knowledge and pediatric release preparation

Status: source engineering only; no runtime deployment, clinical signing, PHI activation or paid mobile build.

## Pediatric preparation

The unsigned range-preparation CLI retains its first five arguments: source directory, allowed source JSON filename, numeric mapping file, exact canonical-LF manifest SHA-256, exclusive-create output path. Pediatric sources additionally require a sixth argument: a reviewed typed-policy JSON file.

The preparer checks package_review.json and pediatric_optimal_ranges.json against the trusted manifest, all eight unique rules and no outstanding holds, source and parent approval metadata, parent activation and exact numeric source references. approved_as_evidence is not an executable-range approval. Approval does not replace V source verification or the existing unit/assay/age/sex/population checks.

The policy has exactly six fields:

- schemaVersion: pediatric-range-policy/1
- packageReviewSha256: canonical package_review.json digest
- adultRangeFallback: disabled
- adultHouseTargets: disabled
- reviewedBy: actual policy reviewer
- reviewedAt: valid non-future UTC timestamp, not before the source policy decisions

No free-text amendment is interpreted as code. Pediatric maxima cannot reach adult ages: 18 years, 216 months or conservatively 6,570 days; inclusive adult boundaries are refused. The conservative day limit can omit a small near-18 interval and must not be represented as exact legal age computation.

Current imported pediatric v1.1.0 has two held rules, so it cannot pass this preparation gate. Its 48 evidence-approved statements and one needs_review statement remain distinct. No current approvals or source text were changed.

## Independent source digest pin

Ask ALP and lab-analysis templates add KnowledgeSourcePackageSha256, mapped to KNOWLEDGE_SOURCE_PACKAGE_SHA256. It is mandatory in reviewed_release mode and unused in disabled mode. This is the exact canonical pearls.json digest, NOT the authoring manifest digest.

The loader still verifies the immutable S3 version, signed payload hash, signer and expiry. It additionally refuses a valid signed payload whose sourcePackageSha256 disagrees with the deployment-owned source pin. Missing/malformed pins refuse before S3 access. This is not automatic monitoring of review-page changes: a revocation must disable the mode or update the controlled release/configuration.

Deploy compatible configuration and code together. Enabled deployments missing the new parameter will fail closed. Existing PHI flags, provider secrets, IAM read scope, signing authority and default-disabled mode are unchanged.
