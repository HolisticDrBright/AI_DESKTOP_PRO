# Consumer registration delivery posture — source candidate only

Production consumer registration previously returned `202 confirmation_required` after `SignUp` even if the pool no longer auto-verified email or Cognito returned no email code-delivery details. On 2026-10-17, a read-only production observation found `AutoVerifiedAttributes` absent on the live consumer pool. The source tests reproduced both false-success paths before this repair; neither test contacted Cognito.

The candidate now reads the exact configured pool before `SignUp` and refuses with a bounded `503 provider_unavailable` unless that pool currently auto-verifies email. After `SignUp`, it requires `UserConfirmed=false` and Cognito's `CodeDeliveryDetails.DeliveryMedium=EMAIL`; if an attribute name is present it must be `email`. A missing, SMS, wrong-attribute or already-confirmed response is not reported as successful registration. The browser/mobile caller already treats a non-2xx response as account-service unavailable. This proves only a provider-reported send attempt, **not** inbox delivery. [AWS describes `AutoVerifiedAttributes` as the attributes to which it automatically sends registration messages](https://docs.aws.amazon.com/cognito/latest/developerguide/user-pool-settings-admin-create-user-policy.html), and [CodeDeliveryDetails as provider delivery details](https://docs.aws.amazon.com/cognito-user-identity-pools/latest/APIReference/API_CodeDeliveryDetailsType.html).

The Lambda's blocked extension candidate adds `cognito-idp:DescribeUserPool` on the exact consumer-pool ARN alongside its existing `DescribeUserPoolClient` permission. A source gate rejects removal of that permission. **Deploy code and the IAM candidate together only after review**: deploying this code against a role without the new read grant will make registration fail closed with 503. The extension still defaults production activation to `blocked`; nothing was deployed, no production account was created, and PHI remains off.

If Cognito creates an account but omits the delivery details, this handler returns 503 after creation. That account may require a later resend/recovery path after the pool configuration is repaired. The existing account-enumeration policy intentionally gives a generic response for a repeated registration attempt; it must not be interpreted as proof of delivery. Hosted acceptance still requires the separately approved production pool repair and controlled fictional registration, resend and reset observed at the owner-controlled inbox. No local mock can close that external case.
