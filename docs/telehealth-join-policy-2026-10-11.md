# Fresh consumer join check

Brandon approved October 11, 2026: after the scheduled end, the patient may join only while the practitioner still has the visit open. Unknown status is not open. This is an app-join policy, not a PHI/provider/security approval.

The additive read-only `POST /clinical-core/consumer/appointments/join` takes exactly `requestId` and `expectedVersion`. It verifies the request owner, discovers the bound appointment and performs one same-table DynamoDB transactional read of the request and visit. A changed request, another owner, pending mutation, cancelled/rescheduled request, closed/ending visit, mismatched clinic/appointment/request/person/meeting/times, absent or future start, ended timestamp or provider shutdown refuses the link. The clock is evaluated after the read. Before the end a scheduled request can use the scheduled window; at or after the end it requires the same practitioner-open `in_visit` record and exact meeting/link. No secret or provider call is made by the check.

The `appointment-join/1` result carries IDs/versions, authority, check time and a maximum 30-second validity window, bounded by the scheduled end for a pre-end check. It contains no notes, passcode, clinical text or email. The V2 client verifies all bindings, URL and time bounds on receipt and immediately before opening, discards private-view/session-late answers and never falls back to a saved link if verification fails. A read-only timeout is unavailable, not an uncertain write. Old deployed APIs without this route refuse new client joining until the matching API is deployed.

The source template is `telehealth-requests/9` with a consumer-JWT route. IAM remains the exact table's existing `dynamodb:GetItem` permission: transactional reads use the underlying item's permissions, not a fabricated `dynamodb:TransactGetItems` action. [AWS transactional IAM documentation](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis-iam.html). An initial implementation added that invalid action; the unchanged IAM test rejected it and it was removed. No test assertion was weakened.

No positive managed, physical-device or two-participant visit is claimed. Current independently verified request factory, per-action appointments/recording authority and matched successor fleet remain unfinished separate engineering. Existing production/PHI and provider gates are unchanged.
